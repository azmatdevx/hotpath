# k6: CI pass/fail

Verify names and exit codes against the k6 version in use.

- Define thresholds in the script. k6 exits with a non-zero code when a threshold fails, which fails the CI step:
  ```js
  export const options = {
    thresholds: {
      http_req_failed: ['rate<0.01'],
      'http_req_duration{name:checkout}': ['p(95)<2000'],
    },
  };
  ```
- Use `abortOnFail` on a threshold to stop a run that is clearly broken, and `delayAbortEval` to avoid aborting during warm-up.
- Export results with `--summary-export=summary.json`, or use `handleSummary()` to write custom output (for example a JUnit or markdown summary for a pull request comment).
- Compare against a stored baseline with a small script that reads the exported summary, since thresholds are absolute.
- Use tags (`name`) on requests so thresholds apply per transaction, and keep tag cardinality low.
