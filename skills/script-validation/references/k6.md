# k6: validation commands

Verify flags against the k6 version in use.

## Single-user pass
- `k6 run --vus 1 --iterations 1 script.js`
- Pass settings with k6's own flag, not a shell prefix (an allowlist rejects `env NAME=VALUE k6 ...`): `k6 run -e BASE_URL=http://localhost:3918 -e TEST_USER=alice --vus 1 --iterations 1 script.js`
- Add `--http-debug=full` to print every request and response. Use `console.log` for variable values, and remove it before the load run.

## Checks and thresholds
- Use `check(res, { 'name': (r) => cond })` for status and content checks.
- Fail the run when checks fail by adding thresholds:
  ```js
  export const options = {
    thresholds: {
      checks: ['rate>0.99'],
      http_req_failed: ['rate<0.01'],
    },
  };
  ```
- Use `abortOnFail` on a threshold to stop early when the script is broken.
- `check()` records a failure but does not stop the iteration. Use `fail()` or an early return for missing required values.

## Timing
- Add `sleep()` for think time, and use scenario executors (`constant-arrival-rate`, `ramping-vus`) to model the workload.

## Data
- Use `SharedArray` to load data once and share it across VUs. Index by VU or iteration to avoid collisions.

## Concurrent pass
- `k6 run --vus 5 --iterations 25 script.js`
- Export results with `--summary-export=summary.json` or `--out json=results.json` for analysis.
