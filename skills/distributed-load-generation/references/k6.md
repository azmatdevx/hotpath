# k6: scaling out

Verify options against the k6 version in use.

- A single k6 process uses many cores, so first check whether a bigger machine is enough.
- **Kubernetes:** the k6 Operator runs a test across several pods (a `parallelism` setting on the test run resource), splitting the load for you.
- **Hosted:** Grafana Cloud k6 runs tests from managed generators, including multiple locations.
- **Manual splitting:** `--execution-segment` and `--execution-segment-sequence` let each machine run a defined fraction of the same test, for example `--execution-segment "0:1/2"` and `--execution-segment "1/2:1"`.
- **Thresholds and results.** With manual segments, each instance evaluates thresholds on its own data. Send results to a shared backend with an output (for example a Prometheus remote write or other supported output) and evaluate there, or merge the exported data.
- Split test data by segment or by instance. Use `SharedArray` per instance.
